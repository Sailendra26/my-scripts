##)Terraform:

*)Terraform is an Infrastructure as Code (IaC) tool developed by HashiCorp. It is used to provision, manage, and modify
  infrastructure resources across multiple platforms using configuration files that define the required infrastructure.

*)It helps automate infrastructure provisioning, maintain consistency across environments, reuse infrastructure , reduce manual effort, 
  and manage infrastructure through version-controlled code.
  
*) .tf is the file extension used for Terraform configuration files. These files contain the required configuration to define and manage infrastructure.
   The configuration files written in HCL (HashiCorp Configuration Language). 

*) Execute Terraform commands only in the path where we have .tf files 

Platforms supported by Terraform:

1. Cloud Platforms:
   - AWS
   - Microsoft Azure
   - Google Cloud (GCP)
   - Oracle Cloud

2. On-Premises & Virtualization Platforms:
   - VMware vSphere
   - OpenStack

3. Container & Orchestration Platforms:
   - Kubernetes

4. Networking & DNS Services:
   - Cisco ACI
   - Cloudflare

5. Other Services:
   - Databases
   - Monitoring Tools
   - Version Control Systems
   - Security & Identity Management Tools
   

NOTE: Terraform uses Providers to communicate with these platforms and manage their resources.

-------------

-> Provision:

Creating and preparing the required resources so they are ready to use.

-> Infrastructure Provisioning:

Creating and preparing infrastructure resources such as EC2, VPC, S3, and Security Groups.

-------------



Providers:
----------

*)Providers are plugins that allow Terraform to communicate with different platforms and services to create and manage their infrastructure resources.

Examples of Providers:

-> AWS Provider
-> Azure Provider
-> Google Cloud Provider
-> Kubernetes Provider
-> VMware Provider



Terraform Basic Commands:
-------------------------

1. terraform init:
   
*)Initializes the Terraform working directory and downloads the required provider plugins and modules.

2. terraform plan:
   
*)Shows a preview of the changes that Terraform will make to create, modify, or destroy infrastructure resources.

3. terraform apply:
   
*)Executes the planned changes and creates, modifies, or destroys infrastructure resources as required.
  By default it asks for confirmation (unless auto-approved).
  
Note:
Terraform apply command ask for user confirmation before executing the changes by default.

To skip the confirmation, use the '-auto-approve' flag. 
Remember: -auto-approve means Terraform executes without asking for your approval. 🫂

Examples:
terraform apply -auto-approve




4. terraform destroy:
   
*)Used to Destroy the infrastructure resources managed by the current Terraform configuration and state.
  By default it asks for confirmation (unless auto-approved).
  
Note:
Terraform destroy commands ask for user confirmation before executing the changes by default.

To skip the confirmation, use the -auto-approve flag.
Remember: -auto-approve means Terraform executes without asking for your approval. 🫂

Examples:
terraform apply -auto-approve
terraform destroy -auto-approve


-> Terraform Execution Flow:

1. terraform init    - Initialize the project.
2. terraform plan    - Preview the infrastructure changes.
3. terraform apply   - Execute the infrastructure changes.
4. terraform destroy - Delete the managed infrastructure.

Resource Block – General Syntax:
--------------------------------

resource "PROVIDER_RESOURCE_TYPE" "LOCAL_NAME" {
    argument = value

    nested_block {
        argument = value
    }
}

Explanation:


1. resource --> Keyword used to define an infrastructure resource that Terraform should manage.

2. PROVIDER_RESOURCE_TYPE --> Specifies the type of resource we want to create.
   Example: aws_instance

3. LOCAL_NAME --> A name given to identify the resource in the Terraform configuration.
   Example: ec2-instance

4. argument --> Specifies a setting name of the resource.
   Example: instance_type

5. value --> The value assigned to an argument.
   Example: "t3.micro"

6. nested_block --> Used to define additional configurations inside a resource block.

Terraform – Resource Naming Rules:
----------------------------------

Same Terraform working folder:

*)Same resource type + same local name → Not allowed

Different Terraform working folders:

*)Same resource type + same local name → Allowed

##) .gitignore:
---------------

*) .gitignore is a file used by Git to specify which files and directories should be ignored and not tracked by Git.

Why do we need it?

- To avoid pushing unnecessary files to GitHub.
- To prevent sensitive files from being uploaded.
- To keep the repository clean.

Remember this distinction:

- New, untracked files → .gitignore prevents Git from tracking them.
- Already tracked files → .gitignore alone won't stop Git from tracking them.

Example:

.terraform/
*.tfstate
*.tfstate.*
*.tfvars


##) Data Types:
--------------


Terraform Data Types:

NOTE:

*)Terraform uses these official data type names when declaring variable types.

Terraform supports the following data types:

1. String:
   Stores text values.

   Example:
   name = "terraform"


2. Number:
   Stores numeric values, including integers and decimals.

   Example:
   instance_count = 2
   cpu_value      = 2.5


3. Bool:
   Stores either true or false values.

   Example:
   create_instance = true


4. List:
   Stores multiple values of the same data type in an ordered collection.
   Each value has a position (index), starting from 0.

   Example:
   instance_types = ["t2.micro", "t3.micro", "t3.small"]

   Index:
   0 → t2.micro
   1 → t3.micro
   2 → t3.small


5. Map:
   Stores values in key-value pairs.
   All values must have the same data type.

   Example:
   instance_types = {
     dev  = "t2.micro"
     prod = "t3.micro"
   }


6. Object:
   Stores multiple named attributes, which can have different data types.

   Example:
   server = {
     name    = "web-server"
     count   = 2
     enabled = true
   }


------------------------------------------------------------------

less important:

7. Tuple:
   Stores multiple values of different data types in a fixed structure.
   Each position has a specific data type.

   Example:
   details = ["terraform", 10, true]

   Position:
   0 → String
   1 → Number
   2 → Bool
   
8. Set:
   Stores unique values of the same data type.
   Duplicate values are not allowed.

   Example:
   availability_zones = toset(["us-east-1a", "us-east-1b"])

------------------------------------------------------------------

Important Differences:

List vs Tuple:
- List → Same data type, ordered collection.
- Tuple → Different data types are allowed, fixed structure.

Map vs Object:
- Map → Key-value pairs with the same value type.
- Object → Named attributes with different data types.

Number vs Integer:
- Terraform uses Number as its data type.
- It supports both whole numbers and decimal numbers.

Bool vs Boolean:
- Both refer to true/false values.
- Terraform uses Bool as its official type name.

NOTE:

Terraform uses these official data type names when declaring variable types.



##) Terraform Variables:
------------------------

1. What are Variables in Terraform?

Variables are used to pass values to Terraform configurations instead of hardcoding values directly in resource blocks.

Why do we use Variables?
- To avoid hardcoding values.
- To reuse the same configuration with different values.
- To make configuration files easy to maintain.
- To use different values for DEV, QA and PROD environments.


#) Variable Declaration:

We declare variables using the "variable" block that contain variable properties such as type, default, description, etc.

Syntax:

variable "variable_name" {

   arguments
   
}   


Example: variables.tf

variable "instance_type" {
  type    = string
  default = "t3.micro"
}

Explanation:
- variable        → Keyword used to declare a variable.
- instance_type  → Variable name.
- type           → Specifies the data type.
- default        → Specifies the default value.


NOTE: Also, you can use any filename for variable declaration but make sure it ends with .tf extension because 
      Terraform automatically reads all .tf files in the working directory.

Examples:
- main.tf
- variables.tf
- bujji.tf



#) Accessing Variables:

We access variables using the "var" keyword.

Example:

resource "aws_instance" "web" {
  ami           = "ami-123456"
  instance_type = var.instance_type
}

Here, 'var.instance_type' accesses the value of the 'instance_type' variable.



#) Providing Variable Values:
-----------------------------

Note: Values provided through these methods override the default values declared in the variable block because Terraform uses the 
      explicitly provided values when the same variable is assigned through these methods. If no value is provided, Terraform uses the default value.


We can provide variable values in different ways. 


1.) Using terraform.tfvars:
----

*)Used to provide values to declared variables through a terraform.tfvars file.
  Terraform automatically loads this file when running commands like plan or apply.

Syntax:

variable_name = "value"

Example:

instance_type = "t3.large"

The value provided in terraform.tfvars overrides the default value if the same variable is declared .


2.) Using CLI argument:
----

*)Used to provide variable values directly through the command line while running Terraform commands.

Syntax: 

terraform plan -var "variable_name=value"

Example:

terraform plan -var "instance_type=t3.large"


3.) Using Environment Variable:
-----

*)Used to provide variable values through system environment variables using the 'TF_VAR_' prefix.


Syntax:

export TF_VAR_variable_name="value"

Example:

export TF_VAR_instance_type="t3.large"


4.) Using Prompt Assignment:
-----

If no default value is defined and no value is provided through other methods, then Terraform prompts the user to enter a value when running terraform plan or apply.



#) Variable File Names:
-----------------------

1. terraform.tfvars.json

- Used to assign variable values in JSON format. Automatically loaded by Terraform.

2. Custom .tfvars files:

- These Custom .tfvars files are used to assign different values to the same declared variables for different environments.
- Custom .tfvars files must be explicitly specified using the '-var-file' option when running Terraform commands such as plan or apply.

Examples:

dev.tfvars
qa.tfvars
uat.tfvars
prod.tfvars

Examples:

terraform plan -var-file="dev.tfvars"
terraform apply -var-file="dev.tfvars"


Note:

- Terraform automatically reads all .tf files in the working directory.
- terraform.tfvars and terraform.tfvars.json are automatically loaded.
- Custom .tfvars files must be specified using -var-file.


Important Arguments inside a variable block:
---------------------------------------------

type - Specifies the data type of the variable.
default - Specifies the default value of the variable.
description - Provides information about the variable.
sensitive - When set to true, Terraform hides the variable value in normal CLI output.It does not encrypt the value.
nullable - Controls whether the variable can accept a null value.




##)Terraform Conditions:
------------------------

Definition:
Conditions in Terraform are used to choose a value or control
resource creation based on whether a condition is true or false.

Syntax:
condition ? true_value : false_value

? = condition true ayithe
: = condition false ayithe

Meaning:
- If the condition is true, Terraform returns true_value.
- If the condition is false, Terraform returns false_value.

Example:

variable "environment" {
  default = "dev"
}

locals {
  instance_type = var.environment == "prod" ? "t3.medium" : "t3.micro"
}

Explanation:
- Terraform checks whether environment is equal to "prod".
- If TRUE → instance_type becomes "t3.medium".
- If FALSE → instance_type becomes "t3.micro".

Output:
For environment = "dev"
instance_type = "t3.micro"

Important:
Terraform conditional expression uses:
condition ? value_if_true : value_if_false

It is also called the ternary conditional expression.



##)Terraform Meta-Arguments:
----------------------------

1. count

*)count is a meta-argument used to create multiple instances of a resource based on a specified number.

Syntax:
count = number

Example:

resource "aws_instance" "server" {
  count         = 3
  ami           = "ami-xxxxxxxx"
  instance_type = "t2.micro"
}

How it works:
- count = 3 → Creates 3 instances.
- count.index → Special value used to access the index of each resource instance.
- count.index starts from 0.

Indexes:
First instance  → 0
Second instance → 1
Third instance  → 2

Usage:
aws_instance.server[0]
aws_instance.server[1]
aws_instance.server[2]


2. for_each

*)for_each is a meta-argument used to create multiple instances of a resource based on the elements of a map or set.
  It is commonly used for looping or repetition in Terraform resource creation.

Syntax:
for_each = map or set

Example:

resource "aws_instance" "server" {
  for_each      = toset(["web", "app", "db"])
  ami           = "ami-xxxxxxxx"
  instance_type = "t2.micro"
}

How it works:
- Creates one instance for each item in the set.
- each.key   → Special value used to access the current key.
- each.value → Special value used to access the current value.
- For a set, each.key and each.value both represent the current item.

Instance references:

aws_instance.server["web"]
aws_instance.server["app"]
aws_instance.server["db"]


Remember:
- count and for_each are Terraform meta-arguments.
- count    → Creates multiple instances based on a number.
- for_each → Creates multiple instances based on a map or set.
- count uses numerical indexes.
- for_each uses keys to identify instances.
- We cannot use count and for_each together in the same resource block.



##)Terraform – Output Block:
----------------------------

Definition:
An output block is used to display useful information about the resources created by Terraform after execution.

Syntax:

output "OUTPUT_NAME" {
  value = ...
}

Example:

output "instance_id" {
  value = aws_instance.ec2-server.id
}

Explanation:
- output is a fixed Terraform keyword.
- "OUTPUT_NAME" → Output name chosen by us. you can write any meaninful name you want.
- value → Specifies which information Terraform should display.

Where to write:
- Output blocks can be written in any .tf file in the same Terraform working directory as Terraform reads all .tf files in the same working directory as one configuration.
- We can write an output block inside variables.tf.
- Creating a separate outputs.tf file is not mandatory.
- outputs.tf is only a naming convention used to organize output blocks.
