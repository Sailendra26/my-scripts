# SDLC — Software Development Life Cycle 💻
-------------------------------------------


# 🔄 SDLC Flow

**Business Requirement
→ Requirements Gathering & Analysis
→ Planning
→ Design
→ Development
→ Testing
→ Deployment & Release
→ Maintenance**

---

**SDLC** is a structured process used to plan, develop, test, deploy & release, and maintain a software application.

## 1) Business Requirement 💼

→ Business ki **em kavalo** identify chestharu.
→ Business goal / problem enti ani understand chestharu.

**Simple meaning:**
**What does the business need?**

---

## 2) Requirements Gathering & Analysis 📝

→ Business/customer/stakeholders nundi **detailed requirements** gather chestharu.
→ Requirements ni clarify, analyze, and document chestharu.

**Example:**
→ User login
→ Product search
→ Add to cart
→ Online payment

**Simple meaning:**
**What exactly should the application do?**

---

## 3) Planning 📋

→ Project ni successfully complete cheyyadaniki **project-level plan** prepare chestharu.
→ Scope, timeline, resources, budget, risks etc. decide chestharu.

**Simple meaning:**
**How will we manage and execute the project?**

---

## 4) Design 📐

→ Requirements base cheskoni software ni **technically ela build cheyyali** ani design chestharu.
→ Architecture, components, database, APIs/interfaces, data flow etc. design chestharu.
→ you design the software application flow here exactly.

**Simple meaning:**
**How will we technically build the software?**

---

## 5) Implementation / Development 👨‍💻

→ Developers actual code write chesi application develop chestharu.
→ Requirements and design ni working software ga convert chestharu.

**Simple meaning:**
**Build the application.**

---

## 6) Testing 🧪

→ Application requirements prakaram work chesthunda ani verify chestharu.
→ Bugs / defects identify chestharu.

**Simple meaning:**
**Does the application work correctly?**

---

## 7) Deployment 🚀 and Release to Users 🌍


→ Developed and tested application ni required/target environment ki deploy chestharu.

**Example:**

Development → Testing → Production

**Simple meaning:**
**Put the application into the target environment.**

---

Release to Users 🌍

→ Application/version ni end users or customers ki officially available chestharu.

**Note:**
Deployment and Release can sometimes happen together, but they are not necessarily the same thing.

**Simple meaning:**
**Make the application available to users.**

---

## 8) Maintenance 🔧

→ Production lo application ni support chestharu.
→ Bugs fix, patches, updates, performance improvements, and enhancements provide chestharu.

**Simple meaning:**
**Keep the application running and improve it.**

---


# 🧠 Easy Interview Explanation

> “SDLC is a structured process used to develop software. First, we understand the business requirement and gather and analyze the detailed requirements. 
Then we plan the project and design the technical solution. Developers implement the design, testers validate the application, and then it is deployed and 
released to users. After release, the application is continuously maintained and improved.”

---

Waterfall:
-----------

Waterfall → fixed sequence → development first → testing later → feedback/defects come late → changes are difficult to make .

Waterfall model is a fixed sequence or fixed plan and the work gets done in phases
Assume a company gets a project from a client with a deadline of two years. In the Waterfall model, the work is done phase by phase.
First, the requirements are collected, then development is completed, and only after that the testing team starts testing. 
For example, developers may work for several months and then hand over the application to the testers.
If testers find defects, the developers need to fix them and testing has to be done again. 
Since testing starts only after development is completed, there may be very little time left before the deadline. 
This can lead to delays, production issues, or delivering a product that does not fully meet the business expectations.
Also, if the business wants to make major changes after development has started, it can be difficult to make those changes because the process is already following a fixed plan.

*)Work happens step by step (sequentially)

Requirement → Design → Development → Testing → Operations

*)Each team works separately as there is no collaboration between all the teams

Developers write code and hand it over to testers only after everything is done.Testers test after full build is ready
After testing is complete, it goes to Operations for deployment

Problems:
---------

*)If issues are found late in testing, it becomes costly and slow to fix

*)No collaboration between Dev, Test, and Ops Teams as they work separately

*)Delivery is very slow

*)Next phase starts only after the current one finishes

#)Devops:
----------

DevOps is a culture, a set of practices, and processes that bring Development, Testing, and Operations teams together to deliver software faster and more reliably.
In traditional approaches, these teams often work in separate stages. In DevOps, they collaborate from the early stages of software development and 
share responsibility for delivering and maintaining the application.
DevOps focuses on collaboration and automation through practices such as CI/CD, automated testing, and infrastructure automation. 
Testing starts early and continues throughout the development process, while the Operations team contributes to infrastructure management, deployment, and monitoring.
This approach enables faster and more reliable deployments, early bug detection, continuous delivery of features, improved product quality, and better collaboration between teams.

-->Earlier in Waterfall, developers wrote code for months, testers waited till the completion, and ops deployed manually — so everything was delayed. 
-->Agile solved the dev and tester delay by delivering in small sprints, but ops delay was still there because deployment was manual. 
-->DevOps fixed that by automating build, test, and deployment and by making dev, test and ops teams work together — so software can go live quickly


DevOps – Practical Example:
----------------------------

Suppose developer 'Login feature' complete chesadu.

• Developer writes the code and pushes it to Jenkins.
• Jenkins builds the code.
• Jenkins runs automated unit/integration tests.
• If the automated tests pass, the application is deployed to the QA/Test environment.
• The tester manually tests the feature, such as the Login feature.
• If the tester finds a bug, it is reported to the developer.
• Developer fixes the bug and pushes the code again.
• The pipeline runs again → Build → Automated Tests → Deploy → Testing.
• Once the feature is validated, it can move to the next stage/environment and eventually to production.

Flow:
Code → Build → Automated Test → QA Deploy → Manual Testing → Fix → Pipeline Again → Production



#)DevOps and DevSecOps:
-----------------------

DevOps:
Security was important in DevOps, but in some workflows, security checks were handled separately or performed late in the development process.

DevSecOps:

DevSecOps stands for Development, Security, and Operations.It is an extension of DevOps that integrates security into every stage of the software development lifecycle.
In DevSecOps, security is a shared responsibility, and we integrate automated security tools into CI/CD pipelines to identify and fix vulnerabilities as early as possible.
For example, we can use SonarQube for code analysis, Gitleaks to detect exposed secrets(passwords), and Trivy to scan container images.
This helps us find and fix security issues early, before they become bigger problems in production.

SonarQube: Used to analyze source code and identify potential security vulnerabilities, bugs, and code quality issues.
