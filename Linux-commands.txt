#)LINUX find COMMAND

Definition:

find is used to search for files and directories within a specified path based on their name, type, modification time, size, permissions, owner, group and  .

Syntax:

find <path> <condition>

IMPORTANT CONCEPT:

*)find searches recursively by default.
*)It searches through files and directories under the specified path.
*)-type f displays only regular files.
*)-type d displays only directories.


QUICK REVISION:

.             --> Current directory
/var/log      --> Absolute path to the log directory
devops/       --> Relative path to the devops directory
-type f       --> Displays regular files only
-type d       --> Displays directories only

-name         --> Searches by name, considering uppercase/lowercase
-iname        --> Searches by name, ignoring uppercase/lowercase
-user         --> Filters by file owner
-group        --> Filters by group owner
-size         --> Filters by file size
-mtime        --> Filters by modification time in days
-mmin         --> Filters by modification time in minutes
-empty        --> Finds empty files or directories
-perm         --> Filters by permissions
-exec         --> Runs a command on each matching item



1. Find files and directories

find /home/devops --> Displays files and directories under /home/devops, including subdirectories.


2. Find only files

find /home/devops -type f --> Displays regular files under /home/devops and its subdirectories.


3. Find only directories

find /home/devops -type d --> Displays directories under /home/devops, including the starting directory.


4. Find files directly inside a directory

find /home/devops -maxdepth 1 -type f --> Displays regular files directly inside /home/devops without entering subdirectories.


5. Find a file by name

find /var/log -name "app.log" --> Searches for app.log under /var/log and its subdirectories.


6. Find files by extension

find /var/log -type f -name "*.log" --> Finds all regular files ending in .log.


7. Find files ignoring uppercase/lowercase

8. Find files owned by a particular user

find /home -type f -user Aaranya --> Finds regular files owned by Aaranya under /home.


9. Find files belonging to a particular group

find /home -type f -group AWS --> Finds regular files belonging to group AWS under /home.


10. Find files larger than 100 MB

find /var/log -type f -size +100M --> Finds regular files larger than 100 MB.


11. Find files modified within the last 24 hours

find /var/log -type f -mtime -1 --> Displays regular files that were last modified less than 24 hours ago.


12. Find old log files

-mtime 7 → Exactly 7 days, 7 complete 24-hour periods.
-mtime -7 → Within 7 days, Less than 7 complete 24-hour periods.

13. Find files modified within the last 60 minutes

find /var/log -type f -mmin -60 --> Displays regular files that were last modified less than 60 mins ago.


14. Find empty files

find /home/devops -type f -empty --> Finds regular files with zero bytes.


15. Find files with specific permissions

find /home/devops -type f -perm 777 --> Finds regular files with exactly 777 permission bits.


16. Display details of matching files

#)Inode, Soft Link, Hard Link – 2-Minute Revision Notes:
---------------------------------------------------------

**)Commnads for memory trick:

*)Soft link → ln -s
*)Hard link → ln


1)Inode:
--------

*)An inode is a number where Linux keeps all the information about a file, like where it is stored, its permissions, and its owner.
*)File name is just a label; Inode is the real file.

*)ls -li --> it shows the file details(permissions, size, owner, etc.) including inode number.
*)ls -l --> it shows the file details(permissions, size, owner, etc.)


2)Soft Link (Symbolic link):
-----------------------------

*)A soft link (symlink) is a file that stores the path of actual file and points to that file, just like a shortcut. 
  If the original file is removed, the link still exists but it will not work.
*)Soft link has a different inode and the original file has different inode.

*)Syntax: ln -s original-file-path softlink-name

Purpose of Soft Link:
---------------------

A soft link provides a common path to access a file or directory.

Real-time Example:

1. An application uses the path /opt/myapp/releases/v2 in many places.
2. When a new version v3 is deployed, we would need to update the path in every place where v2 is used.
3. Instead, we create a soft link named /opt/myapp/current pointing to v2 and use this link path wherever needed.
4. When v3 is deployed, we delete the old soft link and create a new one with the same name, current, pointing to v3.
5. Now, all places using /opt/myapp/current can access v3 without updating each path individually.

Main Purpose:

To avoid updating the new version's path in multiple places. We change the target of the soft link only once, and all references using the common link path continue to work.
 
Examples: 

1)ln -s file1.txt link1.txt --> link1.txt becomes a shortcut to file1.txt.
2)ln -s /home/user/file1.txt mylink.txt --> mylink.txt points to /home/user/file1.txt.
3)ln -s /opt/myapp/releases/v2 /opt/myapp/current
# Creates a soft link named 'current' pointing to v2.If 'current' already exists, the command normally fails.
*)ln -sfn /opt/myapp/releases/v3 /opt/myapp/current
# Deletes the old soft link and creates a new soft link with the same soft link name 'current' pointing to v3.



3)Hard Link:
-------------

*)A hard link is another name for the same file that points to the same inode on disk, The file will be deleted only when all the hard links of a file are removed.
  If the original filename is accidentally deleted, we can still access the file data through the hard link because both names point to the same inode.
*)It uses the same inode for the all hardlink files and for the original file.

*)Syntax: ln original-file-path hardlink-name

Examples: 

1)ln file1.txt hardlink1.txt --> Both file1.txt and hardlink1.txt refer to the same file.

2)ln /home/user/file1.txt hardlink2.txt --> hardlink2.txt is another name for /home/user/file1.txt.


###)Main Difference to remember:

1)Soft link → points to file name
2)Hard link → points to inode
