AWS Route 53:
-------------

*) Route 53 is an AWS DNS (Domain Name System) service that helps connect domain names to the appropriate destinations, such as the IP address of a web server.

*) Route → It routes DNS queries (DNS requests) to the correct destination.
*) 53 → It refers to the standard port number used by DNS.

  
#)What is a Hosted Zone:
-------------------------

*)A hosted zone is a container or place where it contains all DNS records.
*)These records tell DNS how to handle queries(requests) for a specific domain, such as which IP address or destination to use.

#)Types of Hosted Zones : 
--------------------------

1.)Public Hosted Zone : 

Used to manage DNS records that route traffic to an application or website over the internet.

Example: 

*)You have a website www.myshop.com and you want the world to access your application
  In this case, you create a public hosted zone so users from anywhere can access the application.

2.)Private Hosted Zone: 

Used to manage DNS records that route traffic to an application within one or more associated VPCs.

Example:

*)You have an internal application like internal.mycompany.com that should be accessed only by servers inside a VPC.
  In this case, you create a private hosted zone, and it works only within that VPC.

#)DNS Record Types – Definition with Example :
----------------------------------------------

1.) A Record :

*)An A record connects a domain name to an IPv4 address.

Example: If your server IP is 54.20.10.5, when an user hit app.example.com connects to the 54.20.10.5 

2.) AAAA Record :

*)An AAAA record connects a domain name to an IPv6 address.

Example: If your server has an IPv6 address, you use an AAAA record to point the domain to that IPv6 address.

3.) CNAME Record :

*)A CNAME record connects one domain name to another domain name.

Example: www.example.com → myapp.alb.amazonaws.com. Here, www.example.com points to another domain, not an IP.

4. ) MX Record :

*)An MX record decides where emails of a domain should be delivered.

Example: Emails sent to @example.com are routed to the company mail server using an MX record.

5.) Alias Record (AWS Route 53):

*)An Alias record points a domain name to a supported AWS resource, such as an Application Load Balancer or CloudFront distribution.

Example: myapp.com → Application Load Balancer

Meaning:
When a user enters myapp.com in the browser, Route 53 directs the DNS query to the Application Load Balancer, allowing users to access the application through the domain name.

6.) NS Record (Name Server):

*)Name servers are responsible for handling DNS queries for a domain.

Example: example.com → ns-2048.awsdns-64.com

Meaning: The NS record tells DNS which name servers are responsible for managing the DNS records for example.com.

7. ) TXT Record : 

*)A TXT record is used to store verification or security-related information.

Example: A TXT record is added to verify domain ownership for email or security setup.


#)DNS Concepts:
---------------

1. DNS Resolver:
   
*)A DNS resolver receives DNS queries and helps find the IP address of a domain name.

2. DNS Cache:
   
*)DNS cache temporarily stores previously resolved DNS records,including domain names and their IP addresses.

3. TTL (Time To Live):

*)TTL specifies how long a DNS record can be cached before it expires.
300 seconds (5 minutes) → Frequently changing DNS records.
3600 seconds (1 hour) → General-purpose example.
86400 seconds (24 hours) → Stable DNS records.		

4. DNS Lookup(search):
   
*)DNS lookup is the process of finding the DNS record associated with a domain name.


#)DNS Resolution Flow:
--------------------

1. The user enters a domain name (e.g., amazon.com) in the browser.

2. The browser requests the IP address of a domain through the system's DNS resolution process.

3. The DNS resolver checks its cache.

4. If the record exists in the cache and its TTL has not expired:
   - The resolver returns the cached(saved) IP address.

5. If the record is not in the cache or its TTL has expired:
   - The resolver performs a DNS lookup(search) by querying other DNS servers as necessary to obtain a fresh answer.
   - The resolver caches the DNS record according to its TTL.
   - The resolver returns the IP address to the browser.

6. The browser uses the IP address to connect to the server hosting the application.
   
#)Flow:
-------

User enters domain name
        ↓
DNS Resolver checks cache
        ↓
   Cache hit? ── YES ──→ Return cached IP address
        │                       ↓
        NO                 Browser connects
        ↓
DNS lookup(search) to obtain a fresh answer
        ↓
Cache the DNS answer according to its TTL
        ↓
Return IP address to browser
        ↓
Browser connects to the server

#)Making an application available to the public: 
------------------------------------------------

If you want users on the internet to access your application, you must use a domain name.

1)Buy a Domain (from a Domain Registrar):
------------------------------------------

A domain registrar is a place where you buy domain names like ( google.com, facebook.com, amazon.com ).

Common Domain Registrars:

*)GoDaddy
*)Namecheap
*)Hostinger
*)Domain.com

You can choose any registrar based on cost and service.

2)Purchase a Domain (example: Hostinger):
-----------------------------------------

Steps:

1)Open Hostinger
2)Go to Domains → Get a Domain
3)Enter the desired domain name
4)Select domain type (.com, .in, .org, etc.) so For practice, you selected .fun --> Complete the purchase

👉 Domain purchase is done.

3)Give DNS authority to AWS (Route 53):
---------------------------------------

Now, DNS management should be done in AWS Route 53.

Steps:

1)Open AWS Route 53
2)Go to Hosted Zones
3)Create a Public Hosted Zone
4)Enter your domain name
5)Public hosted zone is selected because the application should be accessible from the internet
6)Create the hosted zone

AWS will generate 4 Name Servers (NS records).

4)Update Name Servers in Hostinger :
------------------------------------

Steps:

1)Go to Hostinger → DNS / Nameservers
2)Choose Change Nameservers
3)Select Change Nameservers
4)Remove Hostinger default nameservers
5)Paste the 4 AWS Name Servers
6)Save changes

👉 From now on, DNS is managed by AWS Route 53.

5)Create A Records (after servers are ready):
----------------------------------------------

*)Assume you have 3 servers: (All servers are already set up with required software/code)


A)Frontend server
B)Backend server
C)Database server

A)Database (internal access only):

1)Go to Route 53 → Hosted Zone → Create record
2)Record name: database
3)Record type: A
4)Value: Private IP of database server
5)Create record

B)Backend (internal access):

1)Go to Hosted Zone → Create record
2)Record name: backend
3)Record type: A
4)Value: Private IP of backend server
5)Create record

(Used only by backend, not public users)

C)Frontend (public access):

*)This is what users access from the internet.

1)Go to Hosted Zone → Create record
2)Record name: leave blank for root domain ( because public always use " devopsmegham.fun " this Domain)
3)Record type: A
4)Value: Public IP of frontend server
5)Create record

#)Final Result:

1)DNS is managed by AWS Route 53
2)Internal services use private IPs
3)Users access the application using the public domain
4)Application is now accessible from the internet
